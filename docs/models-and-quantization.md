# 模型与量化选型（8GB 显存单机）

> 本文记录本项目在单机环境下的选型依据。**所有模型权重均不入库**，请按各自主页的许可自行下载。

## 1. 三条链路各自要选什么

| 角色 | 候选 | 关键考量 |
|---|---|---|
| 绘图模型 | Animagine XL 4.0 Opt / NoobAI-XL(Vpred 或 eps) / 各类 Illustrious 微调 | 标签遵循度、角色知识、生态（LoRA / ControlNet 兼容） |
| 打标模型 | WD ViT Tagger v3 系列（timm 版 .safetensors，10861 标签） | 与训练预处理一致（色序 RGB/BGR、是否 padding） |
| 语言模型 | 官方 instruct 小模型（如 Qwen2.5-7B）/ 3B 级中文模型 / 社区蒸馏与去审查微调 | **结构化输出稳定性 > 参数规模** |

## 2. 绘图模型：同尺寸也可能差很多

同一个 SDXL 尺寸（约 2.6B）下，不同训练的检查点在以下维度差异明显：

- **标签遵循 / 角色知识**：数据量与数据源决定（Danbooru / e621 规模越大，角色与 tag 覆盖越广）
- **知识时效**：训练数据截止时间不同，新角色识别能力不同
- **开箱质量**：有的模型"免调参就好看"，有的需要更多提示词功夫
- **v-pred 与 eps**：v-pred 通常对比与色彩更丰富，但**必须手动指定采样类型**（见排障案例 1）、不支持 Karras；eps 更省心
- **显存**：SDXL fp16 检查点约 6.5~6.9GB，8GB 卡可跑，但几乎没有余量留给其它模型

> 结论：**别只看参数量**。本项目最终用"共享底噪 + 同 seed + 同标签串"的 A/B 工作流做选型，
> 而不是看排行榜——因为不同模型的推荐质量词、采样器、先验强度都不同。

## 3. 语言模型：量化是必须的

同一模型不同精度/格式的体积差异（实测数据，便于估算显存）：

| 模型 | 格式 | 体积 | 说明 |
|---|---|---|---|
| Nanbeige4.2-3B | BF16 safetensors（两片） | 8.34 GB | 原始权重，仅微调/transformers 推理需要 |
| Nanbeige4.2-3B | GGUF Q4_K_M | 2.40 GB | 4bit 混合量化，Ollama 日常首选 |
| Nanbeige4.2-3B | GGUF Q8_0 | 4.13 GB | 接近无损，仍只有 BF16 一半 |
| 9B 蒸馏模型 | GGUF Q4_K_M | 5.78 GB | 与 SDXL 同驻 8GB 会紧张 |
| 9B 蒸馏模型 | GGUF BF16 | 17.14 GB | 单机不实用（需卸载绘图模型） |

要点：
1. **参数量 ≠ 文件体积**：3B 的 BF16 是 3×2 字节≈6GB（加未共享的词表/输出层到 8.3GB），Q4 量化到约 1/3；
2. **HF 上的 "model-00001/00002" 是分片**，不是两个模型，缺一片会加载失败；
3. **量化档位选择**：Q4_K_M 是速度/质量平衡点；Q5_K_M、Q6_K 更接近原版；Q8_0 近乎无损；
4. **GQA/词表大小**会让同参数量模型的实际体积有差异。

## 4. 8GB 显存的现实取舍

| 策略 | 做法 | 代价 |
|---|---|---|
| 让 LLM 用后即卸载 | `OLLAMA_KEEP_ALIVE=30s` | 下次调用需要重新加载（数秒） |
| 选更小的 LLM | 3B~4B 级（约 2.4~2.5GB） | 指令遵循能力下降，长指令更容易出错 |
| 量化到底 | LLM 用 Q4_K_M；绘图模型保持 fp16 | 量化过狠会引入格式漂移 |
| 控制出图分辨率 | 832×1216 / 1024×1024 | 高分辨率放大留给后续放大流程 |

**串行优于并行**：绘图与 LLM 不要同时驻留，避免相互挤占导致 OOM 或"看起来卡死"。

## 5. 选模型的检查清单（社区模型尤其适用）

1. **格式**：`library_name` / tags 必须是 `gguf` 才能进 Ollama；`mlx`（Apple Silicon）、`onnx` 等一律跳过；
2. **量化档位是否覆盖你的体积预算**：只有 F16/Q8 的仓库在 8GB 卡上不实用；
3. **元数据**：GGUF 的 `architecture` 是否被当前 llama.cpp / Ollama 支持；`context_length` 多大；
4. **对话模板是否支持关闭思考**：`enable_thinking=false` 或等效开关——不关会导致"思考吃满预算、正文为空"；
5. **热度信号**：下载量/点赞量；同一模型优先选口碑稳定的再量化者（imatrix 量化通常质量更好）；
6. **读 Limitations 段**：作者自陈的问题最可信；
7. **牢记权衡**：去除审查（abliterated / heretic）类微调通常以**能力与格式稳定性下降**为代价，
   而这恰恰是"改标签"任务最怕的——除非确有需要，优先官方 instruct 版本。
